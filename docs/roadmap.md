# vouch — roadmap

This plan follows the 2026-09-27 project audit. The MVP pipeline
(proxy → receipts → verifier → eval) works end to end, but its headline
metrics are measured on a synthetic, self-referential gold set, and
several claims in `docs/design.md` are stronger than the code. The
roadmap raises the ceiling by making the measurement honest and hard
first, and adding features second.

Each phase has exit criteria that are checkable by a command or a
file in the repo. Status: `todo` / `in progress` / `done`.

## Guiding principles

1. **Measurement before features.** A number we cannot defend is worth
   less than no number.
2. **Every claim in docs is backed by a test or a reproducible
   command.** If we cannot back it, we weaken the claim.
3. **Failure modes stay visible.** Known gaps remain in reports.

## Phase 1 — Verifier correctness on real prose

Goal: Tier 2 extraction and matching stop producing the false
verdicts reproduced in the audit, so a real eval (Phase 2) measures the
agent and not our extractor's blind spots.

| Item | Status |
|---|---|
| Dates, years, times, and ordinals are not numeric claims (`2026-07-24`, `Q3`, `50-day`) | todo |
| Magnitude words and suffixes scale values (`12 million`, `$1.2B`, `3.4K`) | todo |
| Multipliers (`3x`) and ranges (`60–65`) are handled or explicitly `UNVERIFIABLE` | todo |
| Entity attribution by clause structure, not character distance (`NVDA's RSI is 62, versus AMD's 48`) | todo |
| Tier 2 claims carry timeframe and as-of when the text states them | todo |
| Multiple candidate facts: no longer "any candidate within tolerance wins"; ambiguous matches get a distinct outcome instead of `SUPPORTED` | todo |
| Regression corpus: hand-written adversarial sentences with expected verdicts, kept separate from the synthetic gold set | todo |
| Property-based tests (Hypothesis) for number parsing and span integrity | todo |

Exit criteria: every probe in `docs/pitfalls.md` under "Verifier" is
fixed and pinned by a test; regression corpus >= 100 sentences.

## Phase 2 — A real evaluation (the headline)

Goal: replace self-referential metrics with precision/recall against
human labels on real agent output. This is what turns the project from
a demo into a measurement.

| Item | Status |
|---|---|
| Task set: 30–50 fixed research prompts over recorded fixtures (replay mode, no network) | todo |
| Agent runner: drive 3–4 models (e.g. Claude, GPT, one open-weights) through the proxy; record answers + receipts | todo |
| Labeling spec and tool: per numeric span, human verdict from the six-verdict taxonomy | todo |
| Labeled set: 200–300 claims; second-pass labeling on a subset for agreement | todo |
| Report: verifier precision/recall per verdict against human labels, with CIs | todo |
| Report: per-model numeric hallucination rate (`CONTRADICTED` + `UNSUPPORTED`), N >= 5 runs per model, variance from actual LLM nondeterminism | todo |
| Gold set decoupled from the extractor: paraphrased answers not generated from `answers.py` templates | todo |
| Remove or relabel metrics that are deterministic by construction (stability on a deterministic pipeline) | todo |

Exit criteria: `make eval-real` reproduces the report from committed
labels and fixtures; README headline numbers come from it.

## Phase 3 — Cryptographic integrity that matches the threat model

Goal: the receipt log's security claims are true and tested.

| Item | Status |
|---|---|
| Ed25519 signatures (public-key verification enables genuine third-party audit); key id on each receipt; HMAC kept only if a reason remains | todo |

| Signed checkpoints (head digest + count) for sealing a session | todo |
| Tamper test suite: delete, truncate, reorder, duplicate, edit fact, edit sig — each must be detected, in both Go and Python | todo |
| `docs/threat-model.md`: attacker, assets, what is and is not protected | todo |

Exit criteria: tamper suite green in both languages; design §3.1
rewritten to match.
